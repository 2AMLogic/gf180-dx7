# asic/orfs — ORFS driver for the dx7-core mapped feasibility run (H10)

OpenROAD-flow-scripts based flow for the gf180mcu **mapped** feasibility
evidence of issue #32 (H10). All components adopted from siblings or the
pinned image are pinned (upstream commit/path/sha256, destination, license,
re-qualification) in `docs/reuse/catalog.json`; the 7t techmaps are
**rederived in-repo** from the pinned image's platform files (DR-0010), not
re-imported from a sibling.

## Files

| File | Origin |
|------|--------|
| `run-orfs.sh` | adopted (single file) from `gf180-parasynth` @ cbcc8b9e, requalified by the H10 end-to-end run; one behavioral deviation from the sibling's later version (Rosetta `--platform=linux/amd64`) is recorded in the catalog entry |
| `sta-corners.tcl`, `check-pdn.py`, `summarize.py` | adopted from `gf180-parasynth` @ `ada47b26` (commit that actually ran the 7t flow); `summarize.py` carries the locally-added `--pdk-root` |
| `gf180_7t/cells_adders.v`, `gf180_7t/cells_latch.v` | rederived in-repo (DR-0010) from the pinned image's `flow/platforms/gf180/cells_{adders,latch}.v` under one documented token substitution; verified per-cell against the 7t tt liberty and by round-trip transform (`tools/verify_gf180_7t_techmaps.py`) |
| `dx7core/config.mk`, `dx7core/constraint.sdc` | this repository (H10) |

`tools/h10_collect.py` (this-repo original, added by H10) assembles the
hash-pinned evidence bundle from these same per-stage reports; the
sibling's `blockarea.py` is superseded by it and not imported.

## Design

One ORFS design, `dx7core`, top = `dx7_core` (the committed H02/H07 RTL:
`rtl/dx7_core.v`, `rtl/env_unit.v`, `rtl/alg_router.v`), SDC clock
40.692 ns (24.576 MHz per DR-0008), `TRACK_OPTION=7t` (D01 constraint),
`CORNER=TC` for the signoff-grade check, `SYNTH_MEMORY_MAX_BITS=65536`
(ROM tables end as standard-cell logic — the H07 method), `LEC_CHECK=0`,
IR analysis off at TC (see `config.mk` comments: sibling-run gotchas, both
documented there with the mechanism).

## FLOW_VARIANTS

| Variant | Die (µm) | Purpose |
|---------|----------|---------|
| `quarterslot` | 1314.88 × 1317.12 | D01 quarter-slot die — fit check vs the 16-note product packaging |
| `twoslot` | 1860.88 × 1862.00 | two-slot die — the sibling-calibrated comparison die |
| `natdie` | sized post-synthesis from the measured mapped area at ~58 % place utilization | natural-die full flow (route, DRC, corner STA at ss/tt/ff) |

Run pattern (`make` stage args after the design name):

```
./run-orfs.sh dx7core FLOW_VARIANT=natdie synth
./run-orfs.sh dx7core FLOW_VARIANT=quarterslot 2_1_floorplan 3_1_global_place
./run-orfs.sh dx7core FLOW_VARIANT=natdie 2_1_floorplan 3_1_global_place 3_5_place_dp 4_1_cts 5_3_finish 6_route ...
OPENROAD_SED=ss OPENROAD_RC=ss ./sta-corners.tcl <openroad> <results-dir> dx7core <pdk-root>
./check-pdn.py <results-dir>
./summarize.py --work-home work --design dx7core --pdk-root <pdk-root>
python3 blockarea.py <global_place.log>
```

`make` invocations are sequential; the machine is shared (DR-0009
concurrency rule: one run per machine, no parallel make jobs).

## What this directory establishes

Area, placement, routing and DRC of the mapped RTL on gf180mcu, and corner
STA at one declared clock. It establishes **nothing** about functional
correctness (that is H02/H07's committed Verilog-vs-model evidence), nothing
about original-DX7 fidelity, and nothing about musical quality. The verdict
table with per-item statuses is generated by `tools/h10_report.py` from the
committed evidence bundle into `docs/H10-GF180-FEASIBILITY.md`.

## Work dir

`work/` is git-ignored build output. The committed evidence for each run
lives in `evidence/h10-gf180/<run>/` (per-stage reports + logs), hash-pinned
by `evidence/h10-gf180/bundle.json` and `evidence/h10-gf180/identities.json`.
